# 성령말씀 올리기

원고나 녹음을 두 저장소의 자동 게시 파이프라인에 **파일 하나만 올려서** 넘기고, 끝날 때까지 확인한다.
데이터(`*.json.enc`)·`sync.json`·`audio/` 는 직접 고치지 않는다. 로봇이 만든다.

## 먼저

1. 저장소 최신 `AGENTS.md` 를 읽는다. 이 스킬과 충돌하면 저장소가 이긴다.
2. 쓰기 권한을 읽기 작업으로 확인한다. 없으면 토큰·비밀번호를 채팅으로 요구하지 말고, 필요한 연결·권한만 알려 준다.
3. 일이 넷 중 무엇인지 정한다. 모호하면 묻는다.
4. **비밀번호(`SAYEON_PASS`)를 채팅·코드·문서·커밋에 쓰지 않는다.** 자동 게시는 저장소 비밀값으로 돌고, 로컬에서 잠긴 자료를 열어야 할 때만 환경변수로 받는다.
5. 올리기 전에 `git pull`(사용자가 다른 기기에서도 올린다). 강제 푸시·기존 파일 덮어쓰기 금지. main 에 올린다(PR 은 요청할 때만).

## A. 글 등록 (성령말씀 N편)

사용자가 "2026년 성령 말씀 N …" 으로 원고를 주면 이렇게 한다.

1. 편 번호 N 확인. 이미 있는 편이면(`audio/N.mp3` 또는 `work-upload/N.json` 존재, 최근 커밋 글) 덮어쓰지 말고 묻는다. 번호가 요청과 원고에서 다르면 추측하지 않는다.
2. 작업표를 만든다. 첫 줄 `2026년 성령 말씀 N` 은 제목 줄이라 `content` 에서 뺀다.

```json
{
  "category": "sayeon",
  "year": 2026,
  "no": 213,
  "title": "성령 말씀 213",
  "content": "첫 문단 첫 줄\n첫 문단 둘째 줄\n\n둘째 문단"
}
```

3. **문단 규칙** — 원고의 빈 줄이 문단 경계, 빈 줄 없이 이어진 줄은 한 문단 안의 줄이다. 줄 순서·줄바꿈·맞춤법·문장부호를 고치지 않는다. 줄 끝은 LF.
   붙여넣은 글은 줄바꿈이 뭉개질 수 있다. PDF 로 받으면 원래 줄 나눔이 보이니 그쪽이 정확하다(쪽이 바뀌는 곳의 문단 경계는 `references/recording.md` 의 '쪽 경계').
4. `python skills/seongnyeong-sayeon-upload/scripts/validate_job.py work-upload/N.json` 로 검사한다.
5. 새 파일로 main 에 커밋·푸시한다. 커밋 글 예 `성령 말씀 213편 원고 등록`.
6. 로봇(`work-upload.yml`)이 이어서 한다 — 글 추가 → 현수 목소리 `audio/N.mp3` → **-16 LUFS 자동** → 문단 시간표 → Pages 재배포 → **새 사연 알림 자동 발송**(마지막 단계, 사용자 기기에 실제로 나간다). 작업표는 처리 뒤 지워진다.
7. 확인. 워크플로 success, 작업표 삭제, `audio/N.mp3` 생김, Pages 배포 success. 실패하면 핵심 로그 원인만 보고하고 우회하지 않는다.

- **현수 음성 단계가 '음성 서버 거절'로 실패하면(2026-11-28, 228편)** 글은 이미 게시돼 있고 알림도 음성 없이 나간다. 우회하지 말고 `work-upload/tts/request.json` 에 `{"number": <편번호>}` 를 올려 '성령사연 남은 편 음성 만들기'를 한 번 다시 돌린다(매일 한국 시간 06:17 에 자동 재시도도 있다). **조심** — 봇이 이 파일을 지우는 커밋이 또 한 번 이 워크플로를 깨우고, 이때는 요청 파일이 없어 `--all`(음성 없는 옛 편 전부)로 돌 수 있다. 그 실행은 즉시 취소한다(`cancel_workflow_run`). 이 경로는 -16 맞춤이 없으니 만들어진 mp3 를 `python tools/loud16.py --fix audio/<번호>.mp3` 로 맞춘다.
- 글 아래 사진(`images`)은 작업표가 받지 않는다. 게시 뒤 로컬에서 따로 넣는다(저장소 `AGENTS.md` '글 맨 아래 사진').
- 기존 편 교체는 사용자가 명확히 말했을 때만 `"replace": true`.
- 시험 실행은 `"dry_run": true`.

## 보고

짧게. 편 번호, 커밋, 워크플로 결과, 배포 결과, **확인하지 못한 것**(듣기·실기기)을 구분해 적는다. 수치로만 확인했으면 "들어 보지 못함"이라고 쓴다.

## 다른 AI(ChatGPT·Codex 등)에서

- 이 폴더 전체를 읽게 하면 된다. `chatgpt-instructions.md` 는 길이 제한이 있는 곳(커스텀 GPT 지침·프로젝트)에 붙여 넣는 요약본이다.
- 필요한 것은 GitHub 파일 만들기·Actions 상태 조회다. 없으면 사용자 계정에 이미 설정된 git·`gh` 로 같은 절차를 한다.
- 오디오 처리(B·C)는 ffmpeg 와 `tools/loud16.py` 가 필요하다. 못 돌리면 파일을 만들지 말고 사용자에게 앱 사용(`/sayeon/upload/`)을 권한다.
- 이 스킬은 Claude Code 에서 만들고 실행해 봤다. 다른 도구에서의 동작은 확인하지 않았다.
