# B. 육성 녹음(m4a) 올리기 — sayeon

글(A)이 먼저 게시돼 있어야 한다(없는 편이면 멈추고 묻는다). 올리는 것은 `recording-upload/<N>.m4a` 하나다. `publish-recording.yml` → `tools/publish_recording.py` 가 문단 시간표(Whisper 정렬)를 만들고 `audio` 칸에 연결한 뒤 이 파일을 치운다.

## 커밋 글 표시 — 가장 중요

| 표시 | 뜻 | 로봇이 하는 일 |
| --- | --- | --- |
| `[원본]` | 날것 녹음 | 잡음은 그대로, **음량만** -16 LUFS·64kbps 모노 48kHz·꼭대기 -1.0 dBFS 이하로 맞춘다 |
| `[소리크기]` | 이미 -16 으로 맞춘 파일 | 그대로 연결 |
| 없음 | 예전 방식 | **잡음 제거까지 돌려 -18.5 로 되돌린다 — 쓰지 않는다** |

- 사용자 결정(2026-11): 육성은 **볼륨만** 맞춘다. 잡음·배경음악 제거는 하지 않는다.
- 파일을 직접 -16 으로 만들면 `tools/loud16.py` 의 `make(원본, 결과, kbps=64, mono48=True, peak_max=-1.0)` 를 쓴다. 낮은 비트레이트 인코딩 뒤 꼭대기가 0 을 넘기 쉬워 `peak_max` 가 필수다. 이미 인코딩한 파일을 또 키우지 말고 원본에서 만든다. 그러면 커밋 글에 `[소리크기]`.
- 이 방식이 번거로우면 `[원본]` 으로 원본을 올리는 편이 쉽다. 올린 뒤 `scripts/check_audio.py` 로 -16 인지 잰다.

## 올리기

1. 파일 이름이 `<N>.m4a` 인지, `.m4a` 인지 확인한다(mp3 로 온 녹음은 이름이 현수 `audio/N.mp3` 와 겹치므로 `audio/<N>-onair.mp3` 처럼 따로 다루며 이 경로를 쓰지 않는다 — 사용자에게 묻는다).
2. 이미 그 편에 육성이 있으면(`audio/N.m4a`) 덮어쓰지 말고 바꿀지 묻는다. 사용자가 직접 보정해 올린 파일(예: 213편)을 임의로 다시 만들지 않는다.
3. 앱은 20MB 까지 한 번에 올린다(조각 올리기가 없다). 그보다 크면 줄여서 올리거나 사용자에게 알린다.
4. 여러 편이면 로봇이 한 파일씩 처리하고, 정렬에 실패한 파일은 건너뛰고 그 파일만 `recording-upload/` 에 남긴다. 실행 로그의 `::error::` 를 본다.
5. 끝나면 봇 커밋이 붙었는지 보고, `audio/N.m4a` 를 받아 `scripts/check_audio.py` 로 잰다(-16±0.3, 꼭대기 0 미만).

## 쪽 경계 (PDF 로 온 원고)

`pdftotext -layout` 만으로는 쪽이 바뀌는 곳이 문단 경계인지 줄 이음인지 알 수 없다. `pdftotext -bbox-layout` 로 쪽마다 첫 줄의 y 를 구해, **다른 쪽들보다 첫 줄이 눈에 띄게 낮은 쪽은 새 문단이 시작되는 쪽**으로 본다. 확신이 없으면 추측하지 말고 사용자에게 그 지점을 묻는다.
